# Changelog

## Unreleased

## 0.9.0 - 2026-11-04

Generated from the API `2026-11-01` document (sha256 `90dfa01c…`). It adds two optional request
fields; nothing else on the wire changed.

### Added

- `Query` on `ListMedicationsRequest`: find medications by name. Every word must appear in the name, in any order, ignoring case
  and accents. The list pager keeps the query on every page.
- `Id` on `Affinity.PatientInput`: the `pat_` ID of a saved patient of the order's practice. The order reuses that patient
  and updates it from the sent fields. An unknown ID, or one of another practice or mode, is a
  `404`.

## 0.8.0 - 2026-11-03

Generated from the API `2026-11-01` document that production serves (sha256 `6806fb50…`).
Requests and responses on the wire are unchanged.

### Added

- `Affinity.PracticeAddressInput`, the type of the `address` you send to create a practice. It has the same fields as
  `AddressInput`.

### Changed

- Creating a practice takes `PracticeAddressInput` as its address (before: `AddressInput`). Orders keep
  `AddressInput`.
- A `413` answer to a get or list call throws `AffinityClientApiException` instead of `ContentTooLargeError`. The API answers `413` only to a
  request with a body.
- The reference and type descriptions name the limits the API enforces: a practice name of 100
  characters or fewer, practice address lines 1 and 2 of 70 characters or fewer together, Windows-1252
  characters without `<` or `>`, and US phone numbers of 10 digits. They also describe the wider
  no-allergy refusal and `restrictedStates`.

## 0.7.0 - 2026-11-03

Generated from the corrected API `2026-11-01` document. Requests and responses on the wire are
unchanged.

### Removed

- `Affinity.MethodNotAllowedError`. The API does not answer `405` to an SDK call. A `405` from a proxy raises `AffinityClientApiException`.
- The `ContentTooLargeErrorBodyCode`, `ServiceUnavailableErrorBodyCode` and their `…CodeCode` types. `ContentTooLargeError.Body` and `ServiceUnavailableError.Body` are now `Problem`, like the other errors.

### Changed

- Clearer descriptions in the types and reference. Every enum member keeps its name.

## 0.6.0 - 2026-11-02

This release is generated from the API `2026-11-01` contract that production serves. That contract
marks each response object and response value list as open: a later API version can add a field or
a value.

### Changed

- Response values keep their known-value types, such as `OrderStatus` and `AllergyCategory`. A response with an
  unknown value or an added field, at the root or nested, decodes without an error: `.Value` holds the unknown value.
- `AdditionalProperties` on every response type is now a writable `AdditionalProperties` (was
  `ReadOnlyAdditionalProperties`), and serializing a response type writes it back.

## 0.5.0 - 2026-11-01

This release targets API `2026-11-01`, which breaks `2026-10-28`.

### Changed

- Every request sends `Affinity-Version: 2026-11-01`.
- A descending sort is `<field>_desc`, such as `ListPracticesRequestSort.CreatedDesc`: `created_desc` and `patient_desc`
  for orders, and `name_desc`, `location_desc`, `mode_desc` and `created_desc` for practices. The
  `-created` values are gone; the API refuses them.
- The shipping destination input types are renamed: `ShippingDestinationInputAddress`,
  `ShippingDestinationInputPatient` and `ShippingDestinationInputPractice` are now
  `ShippingDestinationAddressInput`, `ShippingDestinationPatientInput` and
  `ShippingDestinationPracticeInput`.

### Added

- The `awaiting_approval` order status, in orders, webhook orders and the `orders.list` status
  filter.

## 0.4.1 - 2026-11-01

### Fixed

- Descending sorts are in the sort types: `-created` and `-patient` for orders, and `-name`,
  `-location`, `-mode` and `-created` for practices. Before, the generator dropped each `-` value,
  so a typed call could not reverse a sort.

### Removed

- The `EndingBefore` list parameter. Lists page forward only. After a page fetched with
  `EndingBefore`, the next page also sent the forward cursor, and the API refused it with a 400.

## 0.4.0 - 2026-10-31

This version is generated by Fern (`fernapi/fern-csharp-sdk` 2.92.12) from API version `2026-10-28`. It is a breaking release.

### Changed

- Create the client with `new AffinityClient(apiKey)`, or `new AffinityClient(apiKey, new ClientOptions { ... })` to change the base URL, retries or timeout.
- The client has one property per resource: `Account`, `Feedback`, `Medications`, `Orders`, `Practices` and `Webhooks`. Each method takes one request object, for example `Orders.CancelAsync(new CancelOrdersRequest { OrderId = id, IdempotencyKey = key })`.
- Every write requires `IdempotencyKey` in its request; the SDK no longer makes one. Save it with the reviewed request and reuse it to retry.
- `ListAsync` returns a `Pager<T>` that `await foreach` reads across every page.
- Errors are typed per status (`UnprocessableEntityError`, `NotFoundError` and others) and extend `AffinityClientApiException`.
- Retries default to 2, for 408, 429 and 5xx responses, and wait for `Retry-After`. The timeout defaults to 30 seconds.
- Sends `Affinity-Version: 2026-10-28`.

### Added

- Orders, practices, medications, webhook endpoints, feedback and account, the 17 operations of API `2026-10-28`.
- `docs/reference.md`, the reference for every method.
- A smoke test (`tests/Affinity.Smoke`) that calls every operation against a real API in Test mode, and a webhook signature example in the README.

### Removed

- The patients, catalog, team, locations and signing operations, the facade layer and its scoped clients, and the old Forge pipeline. API `2026-10-28` does not have them.

## 0.3.0 - 2026-10-07

### Changed

- Regenerate from the deployed API contract used by TypeScript SDK 1.16.0.
- Use https://api.affinityrx.com and API version 2026-09-28.
- Add presentation-price reads and remove customer purchase-price writes.

- Use direct API-key constructors, short nested resource methods, and separate request options across all 73 API operations.
- Resolve practice keys automatically and support immutable scoped clients or per-request practice context.
- Generate keys for routine writes, including patient deletion; require persisted keys for consequential order actions.
- Add lazy pagination iterators and consistent API error metadata.
- Accept patient status `archived` as an alias for the API's `inactive` status.
- Default to API `2026-09-28`, a 60-second timeout, and no automatic retries.
- Verify the language guide examples against the implemented client.

## 0.1.0 - 2026-09-29

- Initial C# source preview for Affinity API `2026-09-28`.
- Generated resource clients and models with local packaging and transport checks.
- Registry publishing is deferred.
